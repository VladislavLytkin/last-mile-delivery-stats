# Last-mile delivery stats

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

[Читать выпускную работу в PDF](thesis/main.pdf)

Репозиторий содержит воспроизводимое статистическое исследование связи изменений
зон доставки и режимов работы регионов со скоростью доставки и конверсиями
воронки. В работе используются два обезличенных датасета кейса «Тинькофф:
доставки карт», опубликованного в рамках Национальной олимпиады по анализу данных
DANO 2022–2023.

## Исследовательский вопрос

Как изменения региона обслуживания и режима работы связаны со временем до
первого доступного интервала, назначением и проведением встречи, успешной
встречей в пределах 20 дней и утилизацией продукта в пределах 25 дней?

Основная оценочная стратегия использует панель «гексагон-день», событийную
модель difference-in-differences с фиксированными эффектами гексагонов и дат,
кластерными стандартными ошибками и постоянной контрольной группой, не
подвергавшейся воздействию. Подробная методология приведена в
[`thesis/main.tex`](thesis/main.tex).

## Основные результаты и ограничения

- Для основных конверсионных исходов все 95%-е доверительные интервалы средних
  post-эффектов включают ноль. Исследование не подтверждает универсальный
  однонаправленный средний эффект изменений зон и режимов работы.
- Точечные оценки для успешной встречи в пределах 20 дней равны `-0.72`,
  `-5.98` и `-0.54` п.п. для комбинированного изменения, изменения только
  региона и изменения только режима работы соответственно. Для утилизации в
  пределах 25 дней соответствующие оценки равны `+1.87`, `+2.73` и `+1.04`
  п.п.; интервалы неопределённости во всех этих спецификациях включают ноль.
- Оценки времени до первого доступного интервала равны `+1.181`, `+0.114` и
  `-0.205` дня, но для всех трёх типов изменения выявлены значимые предтренды.
  Поэтому результаты по скорости используются только как диагностика.
- Связь скорости с этапами воронки анализируется как ассоциация, а не как
  причинный эффект. Дополнительные проверки чувствительности не устраняют
  ограничения, связанные с точностью оценок, неоднородностью когорт и короткой
  post-поддержкой поздних когорт.

Проверенный машинно-читаемый снимок результатов находится в
[`outputs/final/`](outputs/final/). Отрицательные результаты, нарушения
предтрендов и ограничения сохранены в полном объёме.

## Установка

Требуется Python 3.11 и [Poetry](https://python-poetry.org/):

```bash
poetry config virtualenvs.in-project true
poetry install --no-interaction
poetry check
```

Poetry и `poetry.lock` являются единственным поддерживаемым способом установки
зависимостей.

## Сборка PDF

Для сборки публичной версии работы требуются XeLaTeX, Biber и `latexmk`, а также
все 22 отслеживаемых публикационных графиков из `figures/empirical/`:

```bash
make -C thesis clean
make -C thesis pdf
cp thesis/build/main.pdf thesis/main.pdf
```

## Размещение данных

После получения файлов из официального источника разместите их так:

```text
data/
└── raw/
    ├── application_dataset.csv
    └── hexagons_dataset.csv
```

Каталог `data/` исключён из Git. Проверка загрузки:

```bash
poetry run python -c "from last_mile.io import load_applications, load_hexagons; print(load_applications().shape, load_hexagons().shape)"
```

## Запуск анализа

Полный расчёт запускается командой:

```bash
poetry run python scripts/run_full_recalculation.py
```

Для него дополнительно необходимы:

- установленный R;
- `Rscript`, доступный в `PATH`;
- R-пакеты `HonestDiD`, `jsonlite` и `readr`;
- исходные CSV в `data/raw/`.

Без R и перечисленных пакетов полный расчёт HonestDiD не выполняется. Оркестратор
исполняет десять исследовательских ноутбуков во временном каталоге, исключённом
из Git, строит диагностики и фигуры, а затем запускает строгий валидатор.

## Проверки релиза

Проверки, доступные сразу после клонирования без исходных данных:

```bash
poetry run python scripts/audit_release_notebooks.py
poetry run python scripts/validate_final_outputs.py
poetry run pytest
poetry run ruff check --no-cache last_mile scripts tests
git diff --check
```

Обычный валидатор проверяет отслеживаемые CSV из `outputs/final/`, собранный PDF
и 22 публикационных графиков. После полного расчёта оркестратор запускает
строгий режим:

```bash
poetry run python scripts/validate_final_outputs.py --full
```

Строгий режим дополнительно требует сгенерированные диагностики и фигуры и не
предназначен для пустого публичного клона.

## Основные каталоги

| Путь | Назначение |
| --- | --- |
| `last_mile/` | переиспользуемая загрузка, фильтрация, исходы и диагностические функции |
| `notebooks/` | EDA, диагностики, основные модели и проверки чувствительности |
| `scripts/` | оркестратор, генераторы, аудит и валидатор результатов |
| `outputs/final/` | отслеживаемый снимок подтверждённых численных результатов |
| `figures/empirical/` | отслеживаемые публикационные PDF-графики; остальные сгенерированные графики игнорируются |
| `thesis/` | основной LaTeX-текст и библиография |
| `thesis/main.pdf` | собранная публичная версия выпускной работы |
| `tests/` | автоматические проверки кода и валидаторов |
| `data/raw/` | исходные CSV, размещаемые пользователем и не входящие в Git |
| `artifacts/` | игнорируемые журналы и временные файлы полного запуска |

Порядок и статус ноутбуков приведены в
[`notebooks/README.md`](notebooks/README.md).
