# Изменения зон доставки: DiD-анализ скорости и конверсий

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

[Открыть текст исследования в PDF](thesis/main.pdf)

В репозитории представлены материалы исследования связи изменений зон доставки
и режимов работы регионов со скоростью доставки и конверсиями клиентской
воронки. Работа основана на двух обезличенных датасетах кейса «Тинькофф:
доставки карт», опубликованного в рамках Национальной олимпиады по анализу
данных DANO 2022–2023.

Публичный репозиторий опубликован как снимок завершённой версии исследования.
Исходные данные, промежуточные расчёты и служебные журналы в него не входят.

## Исследовательский вопрос

Как изменения региона обслуживания и режима работы связаны со временем до
первого доступного интервала, назначением и проведением встречи, успешной
встречей в пределах фиксированного горизонта и последующей утилизацией
продукта?

## Данные

Исходный массив содержит 1 807 426 заявок. После применения правил очистки и
формирования выборки основная панель включает 302 398 наблюдений уровня
«гексагон × день» по 13 255 гексагонам.

В исследовании рассматриваются следующие показатели:

- `t_available` — время до первого доступного интервала;
- `sch_flg` — назначение встречи;
- `meet_flg` — состоявшаяся встреча;
- `success_within_20` — успешная встреча в пределах 20 дней;
- `utlz_within_25` — утилизация продукта в пределах 25 дней.

Исходные CSV не публикуются в репозитории. Порядок их получения и правила
размещения описаны в [`DATA_AVAILABILITY.md`](DATA_AVAILABILITY.md).

## Методология

Основная оценочная стратегия — событийная модель difference-in-differences на
панели «гексагон × день». Спецификация включает фиксированные эффекты
гексагонов и календарных дней, базовую неделю `−1`, кластеризацию стандартных
ошибок по гексагону и постоянную контрольную группу гексагонов без изменения
конфигурации.

Перед интерпретацией результатов проверяются состав когорт, поддержка
событийного времени и динамика показателей до изменения. Дополнительно
используются:

- когортно-временные оценки `ATT(g,t)`;
- анализ чувствительности HonestDiD;
- проверка правого цензурирования и фиксированных горизонтов исходов;
- анализ чувствительности к определению активности гексагонов;
- дозовая спецификация изменения режима работы;
- ассоциативная модель связи скорости с конверсиями.

Подробные определения выборки, исходов и моделей приведены в
[`thesis/main.tex`](thesis/main.tex).

## Основные результаты

- Во всех 12 основных категориальных спецификациях для конверсионных исходов
  95%-е доверительные интервалы среднего эффекта после изменения включают
  ноль. Универсальный однонаправленный эффект изменений зон и режимов работы
  не установлен.
- Для `success_within_20` точечные оценки равны `−0.72`, `−5.98` и `−0.54`
  п.п. для одновременной смены региона и режима, смены только региона и смены
  только режима соответственно.
- Для `utlz_within_25` соответствующие оценки равны `+1.87`, `+2.73` и
  `+1.04` п.п. Во всех перечисленных спецификациях интервалы неопределённости
  включают ноль.
- Для `t_available` получены оценки `+1.181`, `+0.114` и `−0.205` дня, однако
  по всем трём типам изменения обнаружены значимые предтренды. Поэтому эти
  результаты используются как диагностика и не интерпретируются как причинный
  эффект.
- Более длительное ожидание статистически связано с более низкими
  конверсиями, но эта связь является условной ассоциацией и сама по себе не
  показывает эффект ускорения доставки.

Отсутствие статистически значимого среднего эффекта не означает, что
фактический эффект строго равен нулю. Точность оценок ограничивают
неоднородность когорт, короткая поддержка поздних периодов и возможные
отклонения от предпосылки параллельных трендов.

Проверенный машинно-читаемый снимок результатов находится в
[`outputs/final/`](outputs/final/).

## Структура репозитория

| Путь | Содержание |
| --- | --- |
| `last_mile/` | функции загрузки, очистки, построения исходов и диагностик |
| `notebooks/` | EDA, основные модели и проверки чувствительности |
| `scripts/` | запуск полного расчёта, построение графиков и проверка результатов |
| `outputs/final/` | итоговые таблицы в машиночитаемом формате |
| `figures/empirical/` | графики, используемые в тексте исследования |
| `tests/` | проверки ключевых правил обработки данных и согласованности результатов |
| `thesis/` | LaTeX-исходник, библиография и собранный PDF |

В публичной версии `scripts/` содержит только инструменты, необходимые для
повторного запуска анализа и проверки опубликованных результатов.

## Установка

Требуются Python 3.11 и [Poetry](https://python-poetry.org/):

```bash
poetry config virtualenvs.in-project true
poetry install --no-interaction
poetry check
```

Для полного анализа HonestDiD дополнительно требуются установленный R,
доступный в `PATH` исполняемый файл `Rscript` и R-пакеты `HonestDiD`,
`jsonlite`, `readr`.

## Размещение исходных данных

После получения файлов из официального источника разместите их следующим
образом:

```text
data/
└── raw/
    ├── application_dataset.csv
    └── hexagons_dataset.csv
```

Проверка загрузки:

```bash
poetry run python -c "from last_mile.io import load_applications, load_hexagons; print(load_applications().shape, load_hexagons().shape)"
```

Файл `data.dvc` фиксирует ожидаемый снимок входных данных, но публичная
конфигурация не содержит удалённого хранилища с исходными CSV.

## Воспроизведение результатов

Полный расчёт запускается из корня репозитория:

```bash
poetry run python scripts/run_full_recalculation.py
```

После завершения расчёта итоговые таблицы и публикационные материалы можно
проверить командами:

```bash
poetry run python scripts/validate_final_outputs.py --full
poetry run pytest
poetry run ruff check --no-cache last_mile scripts tests
git diff --check
```

Без исходных CSV доступна проверка опубликованного снимка результатов:

```bash
poetry run python scripts/validate_final_outputs.py
```

## Сборка PDF

Для сборки требуются XeLaTeX, Biber и `latexmk`:

```bash
make -C thesis clean
make -C thesis pdf
cp thesis/build/main.pdf thesis/main.pdf
```
